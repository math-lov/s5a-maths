## 4. 題目 JSON 骨架（真實欄位，跟住填）

```json
{
 "id": "ch11-A1", "code": "A1", "type": "mc", "marks": 2, "difficulty": 1,
 "stem": { "en": "…（英文，跟試卷）", "zh": "…（中文）" },
 "keywords": [ { "en": "closed / open circle", "zh": "實心圓點＝包括該數" } ],
 "figures": ["numline-a1"],
 "options": { "A": "$…$", "B": "$…$", "C": "$…$", "D": "$…$" },
 "answer": "B",
 "answers": [ { "math": "x \\ge 4", "note": { "zh": "即選項 B", "en": "Option B" } } ],
 "solution": {
  "steps": [
   { "title": { "zh": "第 1 步 · 讀圖…", "en": "Step 1 · Read the figure…" },
     "math": "x \\ge 4",
     "zh": "…（中文詳解 ≥ 8 字，要講「為甚麼」）",
     "en": "…",
     "marking": "(1M)" }
  ],
  "traps": [ { "opt": "A", "zh": "…", "en": "…" } ],
  "tip": { "zh": "帶得走的技巧", "en": "…" }
 }
}
```

* **MC**：`options` 一定 A–D 四個、`answer` 必須是其中一個、`traps` 只可指向**錯**選項。
* **長題**：`parts[]`（每個 `marks`，加總＝題目 `marks`）＋ 同樣的 `solution.steps`（`marking` 加總亦要對得上）。
  開了「輸入答案核對」（`answerInput`）的課題，`answers[]` 要與 `parts[]` 一對一，每個小題都要有可以核對的 `input` —— 見 §4b。
* **判斷題**（`type: "tf"`）：用 `parts[]` 逐小題列出；`answers[]` 每個小題要有 `part`、`tf`（`true`＝正確／`false`＝錯誤）同 `math`（顯示用，例 `\text{Correct}`）。
  前端會逐小題出「正確／錯誤」兩個按鈕（跟 MC 一樣：錯一次先再試，錯第二次才揭示）；7 小題全對才把整題標記為已掌握。`build.py` S12 會檢查每個小題都有 `tf`。
* **另一個做法（參考）**（選填 `solution.alt`）：`[{ "name": {"zh": "...", "en": "..."}, "zh": "...", "en": "..." }]`。
  前端用 `<details>` 摺疊、**預設收起**、放在題解卡最後（不作為第一解法），標題「另一個做法（參考）」。`build.py` S13 檢查有 `name` 及中英解說（zh ≥ 8 字）。
  用途：計算機核對、坐標法／向量法等補充角度。
* **評分標記風格**：`steps[].marking` 可以在同一步寫多過一個標記（例 `(1M)(1A)`），也可以逐步拆開（一步 `(1M)`、下一步 `(1A)`）。
  兩種都接受 —— **唯一硬要求**是 `steps[].marking` 加總＝題目 `marks`（S2 會查）。現時 `ch17-2` 的 CE1／CE3／CE4 用「逐步拆開」，其餘題目用「串接」，這是老師 2026-09-28 確認的現狀，唔算遺漏。
* **教學卡**（選填，`<節>.json` 頂層 `cards[]`）：顯示在**該節總覽頁（p=0）**，排在簡介卡之後。
  ```json
  "cards": [
    { "id": "ch17-c02", "topic": "ch17-2",
      "title": { "zh": "...", "en": "..." },
      "body":  { "zh": "...用 {{math:0}} 插入顯示數式...", "en": "..." },
      "math":  [ "\\text{Total}\n= (\\text{...})\n\\times (\\text{...})" ],
      "demo":  { "type": "tie-up",
                 "caption": { "zh": "示範用數字：…", "en": "Demo figures: …" } },
      "warn":  { "zh": "常犯錯誤…", "en": "..." },
      "vocab": [ { "zh": "綑綁法", "en": "Bundling method" } ] }
  ]
  ```
  * **互動示範**（選填 `card.demo`）：前端由 `assets/demos.js` 建立，插在**內文之後、「常犯錯誤」之前**。
    `type` 必須在 `build.py` 的 `DEMO_TYPES` 白名單內（S14 會查），`caption` 選填但**建議填**。
    加了示範就要**同步正文的例子**（例：`ch17-c02` 由「3 男 2 女」改成「5 名學生 A–E、A 與 B 相鄰」，兩處數字一致）。
    現況（白名單 `build.py` 的 `DEMO_TYPES`）：`tie-up`（綑綁法，`ch17-2` `ch17-c02`）、`slot-in`（插空法，`ch17-2` `ch17-c03`）、`grouping`（分組，`ch17-3` `ch17-3-c03`）、`combination`、`path`、`complement`（`ch17-3`）、`menu`／`venn`／`code`／`venncalc`（`ch17-1` §9.6）、`floor`（下捨入，`ch18-2` `ch18-2-c02`，見 §9.8）；各有獨立頁 `demos/<type>.html`。
  * **加／改教學卡時的必問一句（老師拍板 2026-09-30）**：AI **一定要主動提醒**「這張卡要唔要互動示範去深化學習？」
    - 若清楚知道「學生為甚麼會不明白」，就直接提出**具體**示範方案（分步按鈕、可點擊對象、即時公式／計數回饋、唔可以劇透答案、跟 `demo` 機制的成本）
    - 若不太明白難點喺邊，就**只提醒老師自己設計**，唔好硬塞一個無意義的動畫
    - 現時 `ch17-2`、`ch17-3` 與 `ch17-1` 的 9 張卡全部都有示範（`tie-up`／`slot-in`／`grouping`／`combination`／`path`／`complement`／`menu`／`venn`／`code`）；`ch10-test`（測驗檢討）暫時未有教學卡
    示範的**數字要同正文例子一致**（今次三張卡都已同步：48、1440、20／10 與 3150／1575）。
  內文用 `{{math:N}}` 佔位符（跟四個站的 learn 內容同一套寫法），前端會換成 `math[N]` 的顯示數式；`math` 條目可以內含 `\n` 斷行。
  **內文逐行處理**：行首 `- ` ＝ 清單項目（「第一步／第二步」分行用），其餘為段落 —— 想步驟分行就在每步前面加 `- `。
  卡內數式區已改為**左對齊、緊湊**（`.cc .formula`）；題解步驟的 `.formula`（居中）不受影響。
  `build.py` **S14** 會查：中英標題／內文、`{{math:N}}` 對得上 `math[]`、數式不可有 `$` 或中文（規則 1）。
* 純數學式直接寫字串（`"$2x+3>3x-1$"`）；**有文字的選項**寫成 `{"en": "...", "zh": "..."}`。

### 4b. 長題「輸入答案核對」（`answerInput` ＋ `answers[].input`）— build.py S19

**為甚麼**：唔想學生「一點即對」。長題會在題目卡下面、題解卡之前出現「輸入答案核對」卡：每小題一個輸入格，按「提交答案」才逐格顯示 ✓／✗，學生一定要自己先計出數字。

* **開關寫在 `data/src/site.json`**：`parts[]` 該項加 `"answerInput": true`（**唔係** part 的 JSON 檔本身；`build.py` 由 site.json 讀，`data/index.js` 亦會把這個 flag 帶出去）。
  已開：`ch17-1`、`ch17-2`、`ch17-3`、`ch17-test`、`ch17-quiz`（第 17 章五個課題）＋ `ch18-2`、`ch18-3`、`ch18-4`（2026-10-16 開）。`ch10-test` 與 `ch18-1`（答案係集合，唔係數字）**未開**，行為完全不變。
* **`answers[]` 要與 `parts[]` 一對一**（S19 會查）。`answers[]` 冇寫 `part` 而數目對得上，build.py 會用 `parts[i].label` 自動補上 `(a)`／`(b)`……（輸入格與答案欄都靠它對位）。
* **`input` 三種寫法**：
  1. **唔寫** → 由 `math` **最後一個 `=` 之後那一段**自動抽（`derive_input()`）。該段**剛好一個數字**（可以含千分位逗號，例 `= 14,400`）或**剛好一個 `\frac{a}{b}`**（例 `= \frac{1}{3}` → `1/3`）才抽得準；多過一個數字就回 `None` 並**報錯**，要作者明寫。
     **符號式答案一律抽唔到**（2026-10-16 加嚴，見 §9.13）：有未知數 `x`／`n`／`k` 的（例 `x\le -5`、`m = \frac{3}{2}n`、`\frac{n}{2^n}`）就算裡面有數字都唔會抽 —— 丟走 `\text{…}`（單位）同 LaTeX 指令名之後，仍有英文字母就回 `None`，要作者明寫 `input` 或 `null`。
     例：`\frac{C^{20}_5 C^{15}_5 C^{10}_5 C^5_5}{4!} = 488864376 \ne 11732745024` 與 `n = 5, 6, 7, 8, 9` 兩題都是明寫的。
  2. **明寫** `"input": "14400"` → 只可以有數字、`.`、`,`、`/`、空格（**唔可以** `$`、LaTeX、中文），而且一定要有數字。S19 亦會查 input 的數字在 `math` 裡面搵得返（防止答案同算式對唔上）。
  3. **明示唔要輸入格** → `"input": null`（例如該小題答案唔係數字）。
* **`inputAlt`（選填）**：`["0.5", "1/2"]` 之類的「其他可接受寫法」，前端會一併接受。**現時全站未用過**（自動抽出來的答案全部都係整數）。
* **前端行為**（`assets/app.js` 的 `answerInputCard()`；樣式 `.ans-card`／`.ans-head`／`.ans-rows`／`.ans-row`／`.ans-input`／`.ans-mark`）：只有「完全未動手」（一格都未對、而且一格都未填）時提交鈕才停用；**提交過之後按鈕唔會變灰**（2026-10-16 老師指示），補填／改完可以再按，每次按都重新核對一次 —— 再按而冇填新答案時會提示「先填答案」（`UI.ansNeedFill`），唔會誤講「有幾格唔啱」；未填的格只會清走舊標記，唔會誤標 ✗。**對**＝✓ 並鎖住該格；**錯**＝✗ 但唔會鎖，改完可以再提交。所有小題都對才把整題記為已掌握（頁碼列亮「已掌握」），進度存在學生瀏覽器 `store.ans["<qid>/(a)"]`。
* **判等規則**（`norm()` ＋ `value()`／`sameValue()`／`same3sf()`；2026-11-11 修正）：全形數字自動轉半形；只移除空格和千位逗號。不可丟掉負號、百分號或其他文字後當成正確數值。判對三步：
  1. **字串相同** —— `10 080`／`10,080`／`１００８０` 都算對；`-0.14`、`0.14%`、`abc0.14` 不等於 `0.14`。
  2. **精確等值** —— `0.25` = `1/4`、`4/52` = `1/13`、`30/32` = `15/16`（有冇約簡都算對）。
  3. **準確至 3 位有效數字**（2026-10-16 老師指示，主要為概率題）—— `1/6` 收 `0.167`、`93/182` 收 `0.511`；`0.17`（只 2 位）、`0.166`（截尾）唔收。
  **整數答案唔可以用第 3 步**（例 `14400`、`12`）：數數目的答案一定要準確，所以 `12.04` 唔會當 `12`。`inputAlt` 的每個寫法都一樣跑呢三步。
* **守門**：`tools/smoke_test.js` 的 **`6b-4. 長題：輸入答案核對`** 一段（五個課題都開了 flag、每個長題答案都有 `input`、B1 兩格／✓✗／鎖格、全形數字、MC 冇輸入卡、未開的 18.1 維持原狀）。

### 4d. Quiz 18 post-quiz review support（2026-11-11）

`data/src/ch18-quiz.json` 每題的 `review` 為選用設定；其餘課題保留原來的溫習流程。

* 英文原題先顯示；中文翻譯和 `parse[]` 拆句按需展開。「顯示完整中英題目」偏好儲存在現有進度資料的 `reviewBilingual`。
* `review.prompts[]`：中英思考問題，不直接揭曉計算；原有逐步題解仍可逐步展開。
* `review.feedback`：以錯誤 MC 選項為 key 的中英提示。`review.answerFeedback`：以長題小題 label、輸入值為 key 的中英提示。
* `review.visual`：`venn`／`block`／`table`／`tree`，附中英 `caption`；表格、樹以 `headers`／`rows` 表示。圖解預設摺疊，學生選擇才揭曉。Venn／綑綁圖為本次題目專用，並非任意參數的繪圖器。
* `review.check`：中英 `prompt`、`choices[]`、零起算 `answer`、答對後 `explanation`、錯誤時 `hint`。此小題不計入試卷分數。
* `store.review[qid]` 分開儲存 `checked`（原題已核對）、`reviewed`（已檢討）、`checkPassed`（小題答對）與 `reasons`（英文／概念／方法／計算／步驟）。原因只儲存在學生瀏覽器，不會傳送給老師。
* 原題答對不再自動計為掌握。原題核對、小題答對及學生勾選「不看題解能解釋」後，再按確認才寫入 `store.done[qid]`；這是自我確認，不是獨立能力的客觀評核。舊 Quiz 18 掌握記錄轉為「已檢討」。
* 重做會收起題解、解鎖原題、清空原題答案／提示及獨立確認，保留檢討記錄和失分原因。舊課題不受這個重做機制影響。

## 6. 內容規則（2026-09-28 老師指示；四個站共用）

1. **數式一律英文** —— `math` 欄位與散文中的 `$…$` 內**不可有中文**（「或」寫 `\text{or}`）；
   中文只出現在**解說文字**。
2. **數式不可以過長** —— 一行過長要分行：先按 `;` 分段（例如 (a)／(b) 的答案各自一行），
   再在 `=`／`\Rightarrow` **之前**斷行，運算符留在續行開頭（每行 ≤ 約 44 顯示字）。
3. **不標籤學生** —— 不寫「補底／落後／後進生／基礎較弱」等字眼；改為描述做法
   （例：「常見直覺：…」「最穩做法」「請把步驟講得夠細」）。
4. **不可用 Markdown `**`**（前端不 render，會原樣顯示）。
5. **運算次序要用中括號寫明**（2026-09-30 老師同意複檢建議，17.1 已全節套用）：凡涉及「先加後減」「先乘再加」「反面減一項」「由方程反求未知」，用 `[ ]` 括住要先算的那一組，並盡量附中間值：
   - `20 + 30 - 3 = 47` → `[20 + 30] - 3 = 50 - 3 = 47`
   - `150 - (60 + 56 - 45) = 79` → `150 - [(60 + 56) - 45] = 150 - 71 = 79`（若整行超過約 44 顯示字，省略中間那步，把中間值寫在詳解文字內）
   - 反求未知：`40 + 30 - x = 60 \implies x = [40 + 30] - 60 = 70 - 60 = 10`（`\implies` KaTeX 支援）
   - 純乘積（`5 \times 5 \times 4 \times 3 = 300`）只有一種運算，唔需要括號。
   `highlight` 跟同一規則，而且**只可以放數式，唔可以有中文字**（17.1 原本有一項寫「供應 250000 = 需求 250000」，已改為 `250000 = 250000`）。
6. **`{{math:N}}` 一定要放在每一點的最後**（2026-10-05 加入守門斷言）：教學卡內文的數式區會獨立成一行，若它後面還有標點或文字，就會出現「只剩下一個。」的孤行。寫法：把推導與解釋寫在前面，最後才 `：{{math:0}}`，之後直接換行。`smoke_test.js` 有斷言檢查教學卡內沒有「只剩標點」的段落。
7. **計算機核對／另一種做法放 `solution.alt`，唔好塞入 `tip`**（2026-09-30 複檢後定案）：`tip` 講「帶得走的數學技巧」（例如「$k$ 為底、$n$ 為指數」、「0 是偶數」）；`alt` 放「另一個做法（參考）」，前端用 `<details>` 摺疊顯示，用途包括計算機核對、互斥區域核對等。例：`ch17-1-ct-32` 的 `alt` 用換底公式 $\frac{\log 1024}{\log 2}$ 求 $n$。**唔好用「保底／補底」等字眼命名方法**（規則 3 不標籤學生），一律寫「另一個做法：…」。

8. **常見錯誤（`solution.traps`）要順次序**（2026-10-16 老師指示）：長題按小題 `(a)→(b)→(c)`，
   MC 按選項 `A→B→C→D`；冇標籤的整題性提示（例如「只答『不同意』而沒有解釋」）排最後。
   `tools/build.py` 的 **S18** 已自動把關，次序錯了唔可以上線。

9. **英文要寫得自然，不要「受控語言」**（2026-11-18 老師指示）：站內**冇**採用 ASD-STE100／
   Simplified Technical English，亦不應模仿那種一句一義、句句祈使、每句都用同一主語開頭的機械寫法
   （老師原話：「英文太生硬了」）。用正常書面英文：可以用 `if`／`when`／`because`／`so` 等從屬句、
   代詞同連接詞，把相關的兩三句連起來；同一段不要每句都用同一個名詞開頭。數學術語
   （vertex、intercepted arc、same segment、cyclic quadrilateral）照用，但不要為了「安全」而犧牲可讀性。
   `tools/verify_ch11_notes.py` 只驗幾何與數式，不約束文風，所以這條靠寫作時遵守。

> ⚠️ 規則 1–4 目前**靠人手遵守** —— `tools/build.py` 的 S1–S9 未覆蓋這四條。
